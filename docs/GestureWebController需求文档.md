## 1. 项目概述

本项目是一款基于 **YOLO 视频手势识别 + 图像识别 + AI 智能问答** 的可复用 Web 工具，完整落地大学生 AI 开发课程核心技术的全流程：

1. **数据库**：数据持久化存储、多表设计、外键关联、CRUD 操作
2. **GitHub**：代码托管、版本迭代、分支管理，基于开源 YOLO 手势仓库二次开发
3. **网页前后端交互**：摄像头视频流传输入、图片/截图文件上传、接口通信、前端 JS 控制页面
4. **图像识别**：三条线路——① YOLO 视频流手势识别（核心）；② 手势触发静态图片识别；③ 手势截屏后 AI 图像搜索
5. **AI 问答**：大模型文本对话，支持将图片/截图识别结果送入大模型做图文问答

**核心能力一句话总结**：
> GestureWebController 是一套可复用的网页手势操控工具，基于 YOLOv8 手势目标检测，前端采集摄像头视频流传给后端推理，识别手势后输出指令，通过 JS 控制当前浏览器页面，实现手势上翻、下翻、截屏、确定、触发图片识别、截屏后 AI 搜索；工具解耦设计，可嵌入任意网页。

## 3. 功能需求

### 3.1 基础通用功能
1. **用户注册登录**：前后端数据校验交互，账号密码校验，信息实时存入数据库
2. **个人中心**：查看编辑个人信息，数据库调取与实时更新（演示数据双向交互 + CRUD）
3. **历史记录**：自动保存所有识别、问答、手势操作记录，可查询、删除

### 3.2 AI 问答功能
- 前端输入文本问题 → 后端 AI 接口 → 对接大语言模型智能答疑 → 回答回显前端
- 对话对实时存入数据库，支持历史回溯
- **图文联动**：可将图片/截图识别结果自动填充到问答输入框，一键提问，打通图像识别 + AI 问答链路

### 3.3 图像识别功能
#### 3.3.1 静态图片识别（原有）
- 用户上传本地图片 → 后端调用图像识别模型解析 → 结果可视化展示 → 存入数据库

#### 3.3.2 YOLO 视频手势识别（核心新增）
- **识别来源**：浏览器摄像头实时视频流，每一帧送入 YOLO 模型检测手势类别
- **推理方式（二选一）**：
  - 方案A（推荐答辩）：前端把视频帧传给后端，后端加载 YOLO 预训练权重推理，返回结果
  - 方案B：前端 WebGPU/ONNX 本地推理（复杂度更高，答辩可选加分）
- **可视化**：视频帧上绘制检测框、手势类别名称、置信度

### 3.4 手势-动作映射表（工具核心）

| 手势 | 触发动作 | 说明 |
| ---- | ---- | ---- |
| ✌️ | 下翻页 | 当前页面向下滚动 / 切换下一页 |
| ☝️ | 上翻页 | 当前页面向上滚动 / 切换上一页 |
| 🖐️ | 截屏 | 抓取当前网页可视区域，生成截图文件 |
| 👍 | 确定 | 模拟鼠标点击焦点位置（提交问答、确认操作） |
| 🤞 | 触发图片识别 | 唤起图片上传，调用后端图像识别模块分析图片内容 |
| 🤟 | 截屏 + AI 搜索（新增核心） | 先执行网页截屏，截图自动提交后端图像识别，返回识别结果展示 |

> **映射可配置**：手势与动作对应关系可在配置文件修改，无需改动 YOLO 推理核心代码。

### 3.5 手势功能细节

**防抖机制**：连续 3 帧识别到同一手势且置信度 ≥ 0.7 才触发动作，防止抖动误触发（答辩加分点）。

**手势触发图片识别（新增功能1）完整链路**：
1. 用户做出指定手势 → 前端唤起图片上传弹窗 / 读取预设图片
2. 图片二进制流发送后端图像识别接口
3. 后端执行图像识别，结果返回前端展示
4. 识别记录存入 `image_record` 表
5. 可选：识别结果自动送入 AI 问答，进行图文问答

**截屏后 AI 搜索（新增功能2 / 答辩最大亮点）完整链路**：
1. 识别到【截屏 + AI 搜索】手势 → 前端调用 html2canvas 捕获当前网页可视画面
2. 截图生成图片文件，自动上传后端（无需用户手动保存、手动上传）
3. 后端接收截图，送入图像识别模型解析截图内容
4. 识别结果回显前端预览；可联动 AI 问答，基于截图内容自动提问
5. 截图文件 + 识别结果 + 手势类型 + 置信度一并入库（截图存入 `image_record`，手势事件存入 `gesture_record`）

> **业务场景举例**：答辩时页面展示文字/图表，比出对应手势 → 网页自动截图 → 立刻识别截图内容 → AI 给出解读。

### 3.6 工具 SDK 封装能力（工具化核心）

**能力边界说明（答辩必须讲，体现专业严谨）**：
- 浏览器安全沙箱限制：JS 不能跨标签页、不能接管整个浏览器窗口
- 全局操控仅限当前激活标签页；截屏只能捕获当前网页内容，不能截取桌面其他软件
- 实现方案二选一：
  - 方案A（推荐答辩，简单稳定）：手势指令发给前端，前端 JS 控制当前页面滚动、截图、模拟点击
  - 方案B：后端服务配合浏览器扩展（Chrome 插件）实现更强全局控制，复杂度更高，作为加分项

**SDK 使用方式（可嵌入任意网页，一行代码初始化）**：
```js
// 初始化
const gestureCtrl = new GestureWebController({
  apiUrl: "http://127.0.0.1:8000/predict",
  enableVisual: true,
  debounceFrame: 3,
  confThreshold: 0.7,
  enableImageRec: true,        // 可选：开启手势触发图片识别
  enableScreenshotSearch: true // 可选：开启截屏+AI搜索
});
gestureCtrl.start();

// 事件回调
gestureCtrl.on("gestureTrigger", (gestureName) => {
  console.log("触发手势：", gestureName);
});

// 新增回调：监听截图+AI搜索完成事件
gestureCtrl.on("screenshotSearchDone", (res) => {
  console.log("截图识别结果：", res.result);
  // 业务层可自定义：把识别文本丢进AI问答
});

// 新增回调：手势触发图片识别完成
gestureCtrl.on("imageRecDone", (res) => {
  console.log("图片识别结果：", res.result);
});
```

**工具化特性**：
- **可插拔**：数据库属于附加日志功能，不启动数据库工具依然可运行
- **低耦合**：YOLO 推理服务独立，前端 SDK 与业务代码解耦
- **可嵌入**：在任意网页引入 JS 脚本即可使用，无需大幅修改原网页代码
- **本地部署**：支持本地一键启动，无需公网服务器

## 5. 数据需求（数据库设计）

采用**关系型数据库**，4 张数据表，通过外键关联。

### 5.1 user 用户表
| 字段 | 说明 |
| ---- | ---- |
| uid | 主键 ID |
| username | 账号 |
| password | 密码（加密存储） |
| nickname | 昵称 |
| role | 权限（普通用户/管理员） |
| create_time | 注册时间 |

### 5.2 gesture_record 手势识别记录表【核心表】
| 字段 | 说明 |
| ---- | ---- |
| record_id | 主键 ID |
| uid | 用户 ID，关联 user 表，未登录用户可为 null |
| gesture_type | 手势动作：上翻/下翻/截屏/确定/触发图片识别/截屏+AI搜索 |
| confidence | YOLO 识别置信度 |
| create_time | 触发时间 |

### 5.3 image_record 图片识别记录表
> 统一存放：手动上传图片识别 + 手势触发图片识别 + 截屏 AI 搜索 的图片识别记录
| 字段 | 说明 |
| ---- | ---- |
| record_id | 主键 ID |
| uid | 用户 ID |
| img_path | 图片/截图存储路径 |
| result | 图像识别输出文本 |
| label | 分类标签 |
| create_time | 识别时间 |

### 5.4 chat_record AI 问答记录表
| 字段 | 说明 |
| ---- | ---- |
| chat_id | 主键 ID |
| uid | 用户 ID |
| question | 用户提问内容 |
| answer | AI 回答内容 |
| create_time | 问答时间 |

### 5.5 数据关联逻辑
- 所有业务表通过 **用户 ID 外键关联** user 表，实现一人对应多条识别、多条问答、多条手势记录
- 数据结构完整，符合课程数据库设计规范，是答辩核心得分点

## 7. 工具整体架构

```
┌───────────── 【前端SDK模块】（可嵌入任意网页）
│  ├─ 摄像头采集模块：获取浏览器 MediaStream 视频流
│  ├─ 帧预处理模块：画面裁剪、缩放，转图像数据传给后端
│  ├─ 指令接收与执行模块：接收 YOLO 识别结果，映射手势→动作
│  ├─ 可视化模块：画面叠加 YOLO 检测框、置信度、当前手势状态
│  ├─ 截屏模块：html2canvas 捕获网页画面
│  ├─ 图片上传模块：手势触发图片识别、截图自动上传
│  └─ 防抖模块：连续 N 帧识别同一手势才触发动作，过滤误识别
├───────────── 【后端推理服务模块】（独立 API 服务，可单独启动）
│  ├─ YOLOv8 手势推理模块：加载开源预训练手势权重，检测手势类别
│  ├─ 静态图像识别模块：分析上传图片 / 截图内容
│  ├─ AI 问答模块：对接大语言模型
│  ├─ 接口服务：接收视频帧/图片/截图，返回 {手势类型,置信度,框坐标} / 识别结果
│  └─ 日志上报模块：识别事件推送至数据库，保存记录
├───────────── 【数据存储模块】（可插拔，不用也能跑手势工具）
│  └─ user / gesture_record / image_record / chat_record 四张表
└───────────── 【GitHub 工程模块】
   ├─ 工具源码仓库，fork 自开源 YOLOv8 手势检测仓库
   ├─ 独立 README：工具部署文档、手势映射配置、使用示例网页 demo
   └─ 版本记录：工具封装、集成、bug 修复提交记录
```

## 9. 完整技术栈汇总（答辩 PPT 要点）

- ✅ **数据库**：4 张数据表，外键关联，CRUD；存储手势日志、图片识别（含截图识别）、AI 问答记录
- ✅ **GitHub**：代码托管、版本分支管理，基于开源 YOLOv8 手势仓库二次开发
- ✅ **网页前后端交互**：摄像头视频流、图片/截图文件上传、接口通信、前端 JS 页面控制
- ✅ **图像识别**：三条线路——① 手势触发本地图片识别；② 手势截屏自动 AI 图像搜索；③ YOLO 手势视频目标检测（核心）
- ✅ **AI 问答**：文本对话；支持将图片/截图识别结果送入大模型做图文问答
